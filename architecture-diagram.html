Neighborhood Safety Check-In Agent — Architecture

Strands Agents SDK · Groq model · AWS Lambda · DynamoDB · SNS · API Gateway · Cognito · EventBridge

Users

  • Volunteers
  • Secretary / Joint Secretary
  • Residents (OTP SMS)
→

React Dashboard

  • Today's check-ins & escalation timeline
  • Admin: assign, reassign, remove people, run agent now
→

API Gateway + Cognito

  • All routes behind Cognito authorizer
  • Role checked server-side in every Lambda
→

AWS Lambda (12 functions)

  • assignCheckIns · markDone (OTP) · reassign
  • add / remove people · run-escalation trigger
↓

⭐ Escalation Agent — Strands Agents SDK

  • Agentic loop: reason → pick tool → act → observe (no hardcoded if/else branching)
  • Triggered by EventBridge every 30 min, or on demand from the dashboard
  • Policy in system prompt: 60 min → reminder · 180 min → secretary · 300 min → joint secretary · 420 min → emergency contact
⇄

Model: openai/gpt-oss-120b via Groq

  • OpenAI-compatible endpoint (OpenAIModel from Strands)
  • Low reasoning effort, 4k token budget for reliable tool calls

Agent's 4 tools

  • get_pending_check_ins — unfinished check-ins + minutes elapsed
  • get_person_by_role — active secretary / joint sec / volunteer
  • send_notification — SNS publish
  • update_check_in_status — advance stage + append audit log

Data & Messaging

  • DynamoDB: Residents, Volunteers, Check-ins (escalationLog audit trail), Sign-in attempts
  • SNS: daily OTP texts + escalation notifications

Schedules & Ops

  • EventBridge: daily assignment 2:30 AM · escalation check / 30 min
  • CloudWatch alarms → SNS email if a job fails or stalls

Auth & Security

  • Cognito user pool (email/password, lockout after 3 failures)
  • Volunteers see only their own check-ins (server-side filter)
  • Synthetic resident data only

Output

  • Dashboard shows each check-in's stage: assigned → reminder → secretary → joint sec → emergency
  • SMS notifications at each escalation
  • Full audit trail per check-in in DynamoDB
